# AGENTS.md

SVG profile cards rendered from a `Stats` snapshot of a user's GitHub contributions. Decisions and their reasons are in `docs/decisions/`. Read the relevant one before changing direction on the language, hosting, data source, counting rules or SVG constraints.

## Layout

- `src/github/`: GraphQL transport and raw fetch. `src/stats/`: the `Stats` type, aggregation and fixture loading.
- `src/designs/<category>/<ID>-<slug>.ts`: one design per file. List it in the folder's `index.ts`. Category-only helpers go in `_shared.ts`; helpers for every category go in `src/kit/svg.ts`.
- `fixtures/`: committed snapshots. `garysassano.json` is real data, `sample-small.json` is synthetic.
- `gallery/`: generated by `pnpm gallery`. Never edit it by hand.

## Rules for designs

- Follow `docs/decisions/0005-svg-rules-for-github-readmes.md`: self-contained SVG, system fonts, at most 840 px wide, dark and light, deterministic.
- `render(stats, theme)` reads only its arguments. It must not read files, the clock, randomness, or contain user-specific literals. When a design has to choose something, it uses a rule stated in `idea`.
- Ids are permanent. Never renumber or reuse one.

## Definition of done

- `pnpm check` passes: Biome, `tsc --noEmit`, Prettier on Markdown, and Vitest. The tests render every design in both themes from both fixtures.
- After changing a design or a fixture, run `pnpm gallery` and commit the regenerated `gallery/`.
- For a visual change, look at a screenshot of the SVG (dark and light) rather than trusting the markup.

## Environment

On the owner's WSL machine memory is tight. Run heavy commands under `systemd-run --user --scope -p MemoryMax=…`, and run Vitest with `--maxWorkers=2` or fewer.
